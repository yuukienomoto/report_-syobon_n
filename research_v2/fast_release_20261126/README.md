# 受領したColab高速版の固定保存

20261126_062849_43a1d6c3 の受領ZIPを snapshot/research_v2 にバイト単位で保存。source_manifest.jsonで27ファイルのSHA256を検証する。旧 features_100 と中断前の features_100_fast は変更・統合していない。

旧固定版との差は features_100/shapes.py と pipeline.py の2ファイル。色別分解・構造的受け入れキャッシュ、fork並列処理、キャッシュ分割、50対局ごとの監査CSV保存を受領版のまま保持する。追加品質評価は署名対象パッケージ外で行う。

## 検証の範囲
受領版の252合成テストがWindows上で成功。実牌譜は実行していない。fork並列はColab/Linux専用で、ローカルWindowsでは未検証。36対局一致、追加30対局監査一致と9.2036倍はユーザー報告。実験ファイルは未受領であり、再確認済みとはしない。validation.json参照。

## キャッシュと再開
同じ固定ソース、C5入力、player、output_root、cache_shards=trueを使用。CLIのpreview→extractで成功キャッシュを再利用する。同時に複数の抽出を走らせない。実行中なら新Notebookの抽出セルは実行しない。

署名はcodeだけでなくC5 sourceにも依存する。パスの末尾 research_v2/ 以下の構造と全ファイルの内容を維持する。ローカルでDrive上のsources.json/complete.json/キャッシュは未取得なので、現物との署名一致はColabで確認が必要。署名不一致時は停止し、署名を書き換えない。品質評価は元のrun_qualityで署名・出力ハッシュ・C5 ID集合を検証する。

JSONは一時ファイルを書いてreplaceする。強制終了時の.lock/.tmpは自動削除しない。実行プロセスが停止済みであることを確認し、対象を別の隔離フォルダに退避してから個別復旧する。完成JSONの署名・checksum・identity検証が先。壊れたJSONを正常扱いしない。ロックにはPID等がないため経過時間だけで解除してはいけない。中断で監査CSVが最大49対局分遅れていても、成功JSONから再構築できる。未保存対局のみ再計算。

## 品質評価
受領quality.pyとN6の方法を維持し、別スクリプトで探索境界の両群窓数、群別Pearson/Spearman相関・対応窓数を追加する。10対局主分析、20対局感度分析。初期1500・17除外、時間帯境界、共通対局除外を維持。境界は全件分布と過去の閲覧履歴を踏まえて理由を記録し、両群がない場合停止。特徴量ごとの有効窓・機会数が足りるかは別途確認する。今回のデータを未使用最終評価と主張しない。

## 残る監査
副露判断記録は受領版では固定副露・点数等の完全なpre-call snapshotを追加していない。旧版との一致だけでは独立検証に十分でない。Z二段階計算の独立検算、未観測21候補・多人数リーチ・終盤・競合の実牌譜正例は継続課題。追加監査は小規模の別成果物として実施し、固定抽出コードを無断変更しない。
