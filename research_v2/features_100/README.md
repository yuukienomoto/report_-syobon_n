# 100候補の共通抽出・検証基盤

設計の基準は `feature_design_100` のコミット `2079e5ba5af5e3401ba458dd27d464a5f717b5f9`。
**100候補を登録し、90候補に計算処理を実装、10候補を未実装として明示した試験版です。**
実装済みの実牌譜での妥当性・観測機会数は未測定です。全100候補が検証完了したとは扱いません。
分類器の学習・AUC比較・既存定義の変更はありません。

## 実行

`feature_extraction_100.ipynb` をColabで開きます。

1. N1：Drive接続、固定コミットからコード取得、別プロセスの依存環境、合成テスト。
2. N2：既存RUN_DIR・対象者・必要ならZIP_OVERRIDEを設定。まずMODE=A。
3. N3：C5署名、対局ID、ZIP内ファイル名と件数の確認。牌譜抽出はしません。
4. N4：Aで各段位期3件（変更可）を抽出。N5で分子・分母・tracesを手牌と照合。
5. 正例・除外・エラーを確認した後、MODE=Bに変更してN2〜N5。全C5対局を抽出します。
6. N2でEXPLORATION_END_HOURを指定しN6。Bのカウンタだけで品質評価します。

既定入力：`/content/drive/MyDrive/卒論/research_v2_runs/20261105T071722Z_5da6c9ad`

既定出力親：`/content/drive/MyDrive/卒論/research_v2_features_100/`

- `<日時_UUID>/`：A/Bの対局カウンタ・監査・定義・レポート。
- `cache/<コードと入力の署名>/`：元XMLハッシュと本人IDに結び付けた対局別JSON。
- `quality/<日時_UUID>/`：Cの結果。前回の結果は上書きしません。

既存C5だけでは選択肢を再現できないため、新90候補の初回抽出には元ZIPが必要です。
C5の旧20特徴量は再抽出しません。成功キャッシュがあればBは再抽出せず読みます。
Bの後にAの詳細判断記録を追加した場合は、その指定対局のみ再生し、保存済みカウンタとの一致を確認します。
同一キャッシュへ複数のランタイムから同時に書き込まないでください。

## 主なファイル

- `extract.py`：本人手牌と公開情報の一回の復元、イベント対応付け。
- `shapes.py`：通常・七対子・国士シャンテン、公開既知枚数に基づく受け入れ、二段の改善余地。
- `options.py`：候補ごとの待ち・現物・完全スジ・ドラ等を共有。
- `rules.py`：打牌・リーチ候補のX/Yと分子分母。保留候補も登録。
- `calls.py`：チー・ポン・大明槓の応答、喰い替え、競合の打ち切り。
- `pipeline.py`：C5監査の再利用、署名・キャッシュ・進捗・失敗保持。
- `quality.py`：非重複10/20対局、機会数方式、探索期間の品質評価。
- `implementation_status.csv`：100候補の状態。
- `tests/`：合成イベント、既知牌姿、候補ごとの判定表、保存・再開・期間分離。

## 出力の読み方

`game_counters.csv`はID別の分子・分母・other・unknown・censored・status・valueを持ちます。
英語名・日本語名との対応は`feature_definitions.csv`にあります。

- `ok`：観測した分母が正で、不明判定なし。
- `no_opportunity`：復元成功だが分母0。値は欠損。
- `unknown`：必要な判定が不明。観測済み分子分母があっても完成した率は欠損。
- `unimplemented`：処理未実装。分子分母も欠損。
- 対局`status=error`：復元失敗。行を消さずCを停止。
- `censored`：副露の競合・終局・接続イベントで応答を観測できない。見送りとして計数しません。

1打牌/提示牌ごとに1機会。第三の合法行動は分母に残し、分子0・other1です。
副露の打ち切り件数は提示牌レベルの監査数で、未観測の合法機会数そのものとは断定できません。
赤の物理コピーによる鳴き方の違いは、同じ牌種形として統合します（今回の副露指標は赤枚数を比較しません）。

## Cの評価

初期1500対局と同一時間帯、段位17、共通対局を従来と同じ規則で除外します。
完全時間帯の境界だけで同一段位群の非重複窓を作り、失敗対局や未抽出対局を詰め直しません。
`order_verified=False`、`full_history_confirmed=False`を維持します。

各窓は分子合計÷分母合計、群内では窓を等重みとします。未知の機会を含む窓は率を保留します。
`group_statistics.csv`、`feature_comparison.csv`、`period_and_exposure_statistics.csv`、
`sampling_noise_reference.csv`、`window_membership.csv`、`partition_counts.csv`を出力します。
100候補分の図は`figures/`に保存します。未実装・機会不足の空図は結果の欠落を示します。

二項分散との比較は独立試行を仮定した参考値であり、真の行動分散の推定ではありません。
分母帯別と期間三分割の表も確認してください。共通元対局の10/20窓比較を`common_games`として併記します。
親候補との比較は`parent_coverage.csv`で対応範囲を明示しています。全100候補の親比較は未完です。

## 中断・不整合

再開は同じコミットのN1〜N4。エラーは`extraction_audit.csv`で対局・局・イベントを確認してください。
キャッシュ破損は自動上書きせずエラーにします。修復前に該当JSONを別名保存し原因を調べます。
異なる実装版では署名が変わるため、旧版の値を混ぜません。ソース/設定を変えたらN3からやり直します。
`.lock`が残る場合は他の実行が終了したことを確認したうえで、その空ロックディレクトリだけを除去します。

役・点数・完全振聴、正例が出ない候補、三人の他家リーチにおけるD08の定義などは
`unresolved.md`を確認してください。
