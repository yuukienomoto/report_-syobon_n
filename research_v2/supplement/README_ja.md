# C6の機会数による10対局集計の追加検証

旧C6は各対局の率を10個単純平均し、10個すべてに値を要求する。機会がない対局では率が未定義になるため、まれな行動の窓が大量に欠損する。

本補足では同じhour_invariant窓・同じ終端ラベルを使い、各窓の分子合計を分母合計で割る。18項目は機会あたりの割合。表ドラ枚数と待ち種類数の2項目は、合計数量を成立リーチ／成立追っかけリーチ数で割る加重平均であり、0〜1の割合ではない。全20項目の加法的な分子・分母は既存のraw_features_v2.csvに保存されている。ZIPの再解析や欠損補完は行わない。列がない、値が不正、元の率と矛盾する場合は停止する。

各窓内では機会数を重みにする。群の平均・中央値・SD・SMDは有効な窓を等重みで集計する。この推定対象を対局単位率の単純平均や全期間のイベント一括集計と区別する。機会の多寡そのものが時期によって異なり得るため、分母の分布と有効窓数も報告する。

従来/追加方式×重複/非重複の4組と、両方式に値がある共通窓の分析を出力する。非重複窓は時刻順に元対局IDの再利用を避けて貪欲選択し、欠損やラベルを見て選ばない。主方式3215窓、非重複547窓という数は利用者の既報であり、本コードで固定せず同じ窓集合の一致を検査して再計算する。

## 実行方法

修正版NotebookのC6の直後にある **C6B** セルだけを現在実行中のNotebookへコピーすれば、C1〜C6の状態と保存先を利用できる。新しく開いたNotebookで実行する場合はC1を実行後、C6Bの `C6_REFERENCE_DIR` に前回のC6保存先（`.../descriptive/<実行ID>`）を指定する。C2〜C6を繰り返す必要はない。元の実行フォルダ内input_plan.jsonとshared_games.csv、キャッシュのcomplete.jsonとraw_features_v2.csvを読み取る。

結果は `卒論/research_v2_opportunity/<新しい実行ID>/` に保存する。C6の保存結果と旧23特徴量比較は読み取り専用の参照先として扱う。

- `aggregation_definitions.csv` に20項目の集計方法・分子・分母。
- `group_statistics.csv` に群ごとの総窓数、有効窓数、欠損率、平均、中央値、SD。
- `aggregation_comparison.csv` に有効窓数の増分、平均差・SMD、方式間・非重複分析の方向一致、共通窓での比較。
- `window_opportunity_totals.csv` と `opportunity_denominator_summary.csv` に機会数。
- `*_windows.csv`、`source_reuse.csv` に窓の値・元対局IDと重複確認。
- `smd_ranking.csv`、`distribution_*.png`、`report_ja.md`、`analysis_settings.json` に比較結果と解釈。

同方向の判定は両群で最低2有効窓を必要とし、符号の一致だけを示す。有効窓が少ない、機会数が少ない、群によって欠損率が違う場合は結論を留保する。重複窓を独立標本とみなす検定や信頼区間は実行しない。非重複窓でも同じ人物の時系列相関は残る。窓終端と履歴の段位混在、時期・卓条件・対戦相手などの交絡も残る。

卒論では、10対局内の行動機会あたりの傾向を測る目的なら機会数集計を主分析の候補とする。従来方式、共通有効窓、元対局非重複の結果で方向と大きさを確認して採否を決める。モデルの入力変更は今回の対象外。

実際に改善した特徴量数と安定した差は、利用者の11,573対局でC6Bを実行した後に判定する。本環境の合成データによるテスト結果を研究結果へ転記しない。order_verified=False、full_history_confirmed=Falseを維持する。
