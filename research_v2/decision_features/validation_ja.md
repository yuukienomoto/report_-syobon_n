# A1・A4・E3・E4 実装と検証

設計仕様は `0078520eafc29cdec706e98316f61cee8a188ed9` の候補CSVと共通定義。既存の20特徴量・追加3特徴量・Notebook・モデルを変更せず、4項目のみ別パッケージに実装した。モデル学習・AUC比較は行っていない。

## 正式仕様との対応

自由打牌Fは通常ツモ後、自己成立リーチ前、鳴き直後でなく、前回自己打牌（局頭はINIT）から誰のカンも挟まない実打牌。自己の今回の宣言打牌は含む。Gは対象者自身の過去の河にある牌種の保有牌、Tは打牌後に既存wait_shapesが非空になる保有牌。

| ID | 分母（1実打牌1機会） | 分子 |
|---|---|---|
| A1 | 単独他家成立リーチ、T非空、現物と非現物を両方保有 | 非現物を選んだ |
| A4 | 単独他家成立リーチ、G/T非空、G∩T空 | 現物を選んだ |
| E3 | 単独他家成立リーチ、現物なし、候補は数牌のみ、完全スジと非スジを両方保有 | 完全スジを選んだ |
| E4 | 複数他家成立リーチ、全員に共通する現物とそれ以外を両方保有 | 共通現物を選んだ |

A1は実打牌でのテンパイ維持を要求しない。E4の概要より正式仕様が厳しく、共通現物しか持たない場合は除外する。人数分の二重計数はしない。E3の4/5/6は両側スジを要求し、片スジは非スジ。字牌が1枚でも候補にあればE3から除外する。

## 再利用と状態検査

`tenhou.decode_meld/is_suji/wait_shapes`、`choices.tenpai_options`を再利用。新リプレイは本人の手牌・ツモ、公開河・副露、REACH step2だけから判断直前の選択肢を作る。他家INIT手牌・非公開ツモ内容は読まない。DORAや終局公開情報は本4項目には不要であり計測に使わない。

打牌を手から除く前に計数する。自分の副露牌込みの物理ID重複、手牌長、実打牌、呼ばれた直前の牌、加槓の元ポン、宣言打牌後の成立を検査。再接続REINIT、三人打ち、不整合・途中終了は失敗とする。自由打牌からの除外と、特徴量別の条件不成立は別々にイベント監査に残す。

C5の完了署名、元抽出器ハッシュ、CSV・監査ハッシュ、対象者・対局集合を照合し、旧`_final_frame`を利用。各試験XMLは展開後SHA256をC5と照合。**少数試験に限り**旧20抽出器でも復元し、キャッシュの40個の分子・分母と局数・打牌数を照合する。既存20の全件再抽出や保存し直しはしない。対象者は引数で指定し、外部対象をしょぼんｎと偽らない。

初期1500観測対局と同じ時間帯まで、共通対局、段位17を除外。主基準は16以下/18以上のまま。17を低/高に含む2条件は後続の感度分析として保持する。本pilotは17段を選択しないが、元C5台帳から削除しない。

## 検証範囲と残課題

- 新規テストは合成イベント・既知牌姿・実牌譜抜粋・キャッシュ/台帳結合を含む。現物のみ/なし/混合、現物テンパイ両立/不両立、実打牌ノーテン、字牌、片スジ、複数リーチの1打牌1計数、自己宣言/成立、鳴き、暗槓・加槓・大明槓、未来/非公開情報不変、失敗保持、再開、改変拒否を確認。
- 旧抽出・入力・開示例外・追加3・平滑化の関連テストも再実行する。テスト件数と結果は同ディレクトリの `test_results.json` に記録する。
- 高段位期、E3/E4の正例、複数リーチ、カンの実牌譜照合は未完了。合成成功を実牌譜全体の検証と混同しない。Drive上の低・高段位試験は未実行。
- 手元の1対局が初期1500除外後の対象かはC5台帳にアクセスできず未確認。これは復元試験であり、主分析対象から得た群間差ではない。
- 手牌形状は七対子・国士・副露・暗槓を含む既存関数を使用するが、役・フリテン・公開牌残数は評価しない。受入・シャンテン・打点・意図・安全確率は追加していない。
- 同一時間帯内順序、全履歴完全性はFalseのまま。10/20窓は元台帳に対して従来`make_blocks`で作り、全対局が揃う窓だけ利用。少数抽出を詰めない。失敗がある時は窓集計全体を止める。
- 10/20窓の分母分布はローカル未測定。機会が特定局へ集中する問題、同一局内の依存も結果を読む際に確認する。

## Colab手順と入力

`decision_feature_pilot.ipynb` のP1→P6を実行する。

1. P1：Drive接続、固定コミットのコード取得、独立した依存フォルダでテスト。Colab本体のnumpy等を置き換えず、別プロセスで解析する。
2. P2：`RUN_DIR`（input_plan.jsonとshared_games.csvを含む既存実行フォルダ）、`PLAYER`、`KEY`を設定。既定は `卒論/research_v2_runs/20261105T071722Z_5da6c9ad`。実牌譜ZIPは計画に記録されたパスを利用し、移動していれば`ZIP_OVERRIDE`を設定する。C5 CSVだけから新機会を復元することはできない。
3. P3：入力監査と対象ID確認。既定は低3・高3の計6対局を各段位期の前・中・後から固定抽出。ID順は同時間帯内の真の順序とは解釈しない。追加の局面を試す場合は事前に`EXPLICIT_IDS`を設定（最大60件）。抽出後に都合のよい特徴量値で選び直さない。
4. P4：表示した少数対局だけを抽出。P3からコード・対象・入力が変わっていれば停止。中断後はP1〜P4で成功キャッシュを再利用。失敗対局は監査に残し、修正なしに分母0として続行しない。
5. P5：分子・分母、欠損、除外、失敗、局への集中、窓の測定可否を表で確認。
6. P6：日本語レポートと保存先確認。

出力は `卒論/research_v2_decision_features/<日時_識別子>/`。P4再実行でも別フォルダとなる。成功キャッシュは同じ親の `cache/<署名>/<IDとXMLのハッシュ>.json`、元C5/ZIPは読取専用。コード・XML・入力署名が異なるキャッシュは互換扱いしない。

主要出力は `selected_games.csv`、`game_features.csv`、`extraction_audit.csv`、`feature_opportunities.csv`、`decision_events.csv`、`decision_traces.json`、`exclusions.csv`、`round_concentration.csv`、`window_coverage.csv`、`window_opportunities.csv`、`report_ja.md`。計数だけでなく判断直前の選択肢を照合してから、後続の抽出範囲を決める。
